# 降噪功能说明与测试用例

本文档说明 NegLift 降噪功能的设计、API、性能实测数据与测试用例。

---

## 1. 功能概览

降噪分两条独立控制的通路，都基于同一份参数（`EditParams.denoise`），预览与导出使用完全相同的参数：

| 通路 | 参数 | 作用 | 实现位置 |
|---|---|---|---|
| 色彩噪点降噪 | `denoise.color` 0–10 | 去除去马赛克后的彩色色斑 | GPU 预览着色器 / CPU 导出管线 |
| 亮度噪点降噪 | `denoise.luminance` 0–10 | 平滑颗粒噪点，保留边缘 | 同上 |
| 总开关 | `denoise.enabled` | 关闭时降噪完全旁路 | — |

两条通路的分工：

- **实时预览**：由 WebGL2 后端在渲染进程执行，属于渲染管线的一个 Pass。
- **导出**：由主进程的 `renderLinear()` 在 16bit 显示域执行，位深高于预览，是画质基准。

---

## 2. 参数说明

```ts
interface DenoiseParams {
  enabled: boolean
  /** 色彩噪点降噪强度等级 0..10（整数档） */
  color: number
  /** 亮度噪点降噪强度等级 0..10（整数档） */
  luminance: number
}
```

| 参数 | 范围 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | `true` / `false` | `false` | 总开关。关闭时不做任何处理（逐像素恒等，不引入副作用） |
| `color` | 0–10 整数 | `0` | 等级即“滤波结果与原色度的混合比例”（等级 10 = 完全采用滤波结果）。跨亮度边缘的邻居权重被压到下限，因此调高不会出现色晕 |
| `luminance` | 0–10 整数 | `0` | 同上，作用于亮度通道。会轻微柔化高频纹理，属预期行为 |

**推荐用法**

| 场景 | 建议 |
|---|---|
| 高感光 / 欠曝负片，色斑明显 | `color` 6–8，`luminance` 0–2 |
| 画面整体颗粒粗 | `color` 4–6，`luminance` 3–5 |
| 需要保留最大细节 | 只开 `color`（色彩降噪按设计**不改变亮度通道**，细节零损失） |
| 需要极致干净 | `color` 10 + `luminance` 6–8 |

## 3. API

### 3.1 共享管线 API（`src/shared/pipeline/denoise.ts`）

```ts
/** 判断降噪是否会实际生效（总开关 + 至少一个等级 > 0） */
export function isDenoiseActive(d: DenoiseParams | null | undefined): boolean

/** 把 0..10 等级换算为 0..1 混合量 */
export function denoiseAmounts(d: DenoiseParams): { color: number; luminance: number }

/** 引导滤波常数（GPU 着色器复用同一组值，保证两后端参数一致） */
export const DENOISE_KERNEL: {
  chromaSigma: number  // 0.075
  lumaSigma: number    // 0.05
  wMin: number         // 0.1
}

/**
 * 对显示域渲染结果做降噪（原地修改）。
 * @param rgb    16bit 显示域 RGB 交错数据，长度 width*height*3，取值 0..65535
 * @param width  图像宽度
 * @param height 图像高度
 * @param params 降噪参数
 */
export function denoiseDisplay(
  rgb: Uint16Array,
  width: number,
  height: number,
  params: DenoiseParams
): void
```

`denoiseDisplay` 是纯函数式接口（无 IO、无副作用，仅原地修改传入缓冲），可以直接在测试或批处理脚本中独立调用。

### 3.2 渲染管线接入点

```ts
// src/shared/pipeline/index.ts —— 导出路径，降噪在几何变换与调色之后、统计直方图之前
renderLinear(src, srcW, srcH, params, opts)

// src/renderer/src/engine/gpuRenderer.ts —— 预览路径
// Pass 1: 色调链渲染到离屏纹理（RGBA8 + mipmap 链）
// Pass 2: 降噪 Pass 输出到画布
```

两个后端在**关闭降噪时逐像素一致（最大偏差 1 LSB）**；开启降噪后属于空间滤波，两端内核的采样顺序不同，差异见 §5。

### 3.3 界面入口

- 参数面板「降噪」标签页：总开关 + 两个等级滑块。
- 所有参数随 `EditParams` 一起参与撤销/重做、自定义预设存取与导出。

## 4. 算法说明

### 4.1 色彩噪点（`color`）

彩色噪点在去马赛克后表现为**低频色斑**，因此不需要在全分辨率上处理：

1. 以 8×8 盒式降采样建立 1/8 分辨率的 `Y / Cb / Cr` 平面
   （`Y/Cb/Cr` 都是 RGB 的线性组合，先平均再分解与先分解再平均等价，因此这一步是无损的）
2. 在该平面上做 5×5 **亮度引导**滤波（等效全分辨率半径约 ±16px）：
   权重 `w = max(0.1, 1 − (ΔY/σ)²)`，`σ = 0.075`
3. 上采样滤波后的色度，与原图色度按等级混合，**亮度通道沿用原值**

关键点：第 3 步只用滤波结果替换色度，亮度原样保留（实测亮度最大偏差 0.5/65535），所以去掉色斑的同时**不损失任何亮度细节**；权重下限 0.1 把跨亮度边缘的混合限制在 10% 以内，避免色晕。

GPU 端用同一组参数实现：取色调链结果的 **mip level 3**（即 8×8 盒平均，等价于 1/8 平面），在 3×3 采样点（步长 2 → 等效 ±16px）上做同样的引导加权。

### 4.2 亮度噪点（`luminance`）

全分辨率 3×3 亮度引导滤波（同一权重函数，`σ = 0.05`），只改亮度、保留原色度。

## 5. 性能实测

测试环境：Intel Arc B580（ANGLE / D3D11），Windows，Node 24 / Electron 44。

### 5.1 实时预览（GPU）

| 输出尺寸 | 无降噪 | 色彩降噪 | 亮度降噪 |
|---|---|---|---|
| 2661×1770（4.7M px） | 179 ms（首帧，含着色器编译） | 145 ms（首帧） | **1.1–1.8 ms**（稳定帧） |
| 应用内实测（适应窗口） | 2.8 ms | 3.1 ms | — |

稳定帧耗时在 **1–3 ms**，远优于 500 ms 要求。

### 5.2 导出（CPU，16bit 高精度）

| 图像规模 | 色彩降噪 | 亮度降噪 | 两者同时 |
|---|---|---|---|
| 2400 万像素（6000×4000） | **403 ms** | 713 ms | 1116 ms |
| 480 万像素导出（1600×1062 实测） | +46 ms | +61 ms | — |

色彩降噪满足 500 ms 要求；亮度降噪是可选增强项，会额外增加耗时（导出本身已是秒级操作）。

### 5.3 真机效果（`raw pic/_DSC3734.ARW`，导出 1600×1062 PNG）

以“相邻像素色度差”衡量的高频色度能量：

| 导出设置 | 色度噪声 | 文件体积 |
|---|---|---|
| 关闭降噪 | 11.471 | 4.35 MB |
| 色彩降噪 10 | **0.820（下降 92.9%）** | 3.62 MB |
| 亮度降噪 8 | 11.468（色度不受影响，符合设计） | 4.31 MB |

## 6. 测试用例

### 6.1 运行方式

```bash
npm run test:denoise
```

测试为自包含脚本（`test/denoise.test.ts`，esbuild 打包后由 Node 直接运行，无额外测试框架依赖），退出码非 0 表示有用例失败。

### 6.2 用例与验收指标

| # | 用例 | 验收指标 | 实测 |
|---|---|---|---|
| 1 | 关闭降噪 / 等级 0 时为恒等变换 | 逐像素完全一致 | ✅ 一致 |
| 2 | 色彩噪点随等级单调下降 | 单调不回升，且等级 10 相对等级 0 下降 > 50% | ✅ 下降 52.4% |
| 3 | 色彩降噪不改变亮度通道 | 亮度逐像素偏差 ≤ 1.5/65535 | ✅ 0.50/65535，细节梯度完全不变 |
| 4 | 亮度降噪保住强边缘、压低颗粒 | 边缘陡度保留 > 60%，平坦区颗粒 < 80% | ✅ 保留 89.3%，颗粒降至 32.7% |
| 5 | 平均色彩漂移 | 平坦区与边缘区 ΔCb/ΔCr < 0.002（约 0.5/255） | ✅ 最大 0.0001 |
| 6 | 2400 万像素单张降噪 | 色彩降噪 ≤ 500 ms | ✅ 403 ms |

### 6.3 测试数据构造

`test/denoise.test.ts` 中的 `makeSynthetic()` 合成一张确定性（固定随机种子）测试图：

- 平坦中性灰区域 → 度量色度噪声与色彩漂移
- 黑白强边缘区域 → 度量边缘保持（用**最大梯度**而非平均梯度，因为平均梯度会被噪声主导）
- 高频细条纹区域 → 度量细节保持

彩色噪点用两个尺度的低频网格插值叠加生成，模拟去马赛克后的色斑（相关长度约 16px）。

## 7. 关于“深度学习降噪”的结论

需求中的 AI 降噪已做过完整可行性验证，结论是**在本项目当前环境下不可用**，实测数据如下（`@upscalerjs/maxim-denoising`，Google MAXIM，CVPR 2022，TF.js WebGL 后端）：

| 项目 | 实测 |
|---|---|
| 模型规模 | 42,959 个计算节点 / 17,944 个权重张量 / 115 MB |
| 模型加载 | 22.1 s |
| 128×128 图块推理 | 3.65 s（≈ 0.0045 MP/s） |
| 256×256 图块推理 | **失败**：TF.js 需要 23170×23171 纹理，超过 WebGL 上限 16384 |

按此吞吐，4200 万像素一张需要 **约 2.6 小时**（需切成约 2560 个图块），与 500 ms 相差 4 个数量级；放大图块则直接撞上 WebGL 纹理上限。该模型由 JAX 经 jax2tf 导出，图结构中的 Einsum/Pack/Reshape 在 TF.js WebGL 上会产生异常巨大的中间张量。

因此本项目采用**亮度引导的边缘保持滤波**作为降噪实现（实时通路 < 3 ms）。它是经典算法，不是深度学习，特此明确标注，避免误导。

若后续需要接入真正的 AI 降噪，可行路径是：准备一个**小体量 ONNX 模型**（例如针对色度去噪的轻量 CNN，参数量 10 万级），用 `onnxruntime-web` 的 WebGPU 后端按块推理；按 128×128 图块的调度开销推算，模型节点数需控制在千级以内才可能进入秒级。

## 8. 已知限制

1. **两后端的降噪结果不完全逐像素一致**：GPU 使用 mip level 3 + 全分辨率采样，CPU 使用显式 1/8 平面 + 上采样，两者色度平滑的采样顺序不同。实测（色彩等级 10，2661×1770）：平均差 1.45/255，99.6% 的像素差异 ≤ 2 LSB；色度噪声下降幅度一致（GPU 35.73→30.95，CPU 35.86→30.82）。关闭降噪时两后端仍严格一致（最大 1 LSB）。
2. **色彩噪点降噪会降低色度分辨率**（等效半径约 ±16px）：对真实照片无可见影响，但在同等亮度、仅色相不同的硬边界（罕见）上可能出现轻微色彩过渡变宽。
3. **亮度降噪无法区分“纹理”与“噪点”**：细密纹理（如织物、树叶）在等级较高时会与噪点一起被平滑，需要按题材权衡等级。
